## Decisions

- Validate the exact `Workflow` object that execution dispatches on both fresh and resumed runs; reject before provider/stage dispatch. Reject error-severity graph violations; warning-only findings remain non-fatal.
- Answered parks are selected by exact stable stage identity and the lowest unconsumed run-scoped park sequence (`n`); prompt text is context/display only. Cover changed prompt text and repeated identical prompts.
- Cross-process exclusion covers every writer of the same run, fresh or resumed, not unrelated workflows. Both entry points use `withRunLease` and the existing atomic `acquireResumeLock(cwd, runId)` before header publication/reconstruction or dispatch; hold the lease through provider disposal and release by token in `finally`. Refuse live owners and recover dead owners only through verified PID/token checks.
- Global workflow execution provider registrations use one process-global ordered token stack. Disposing any token is idempotent and cannot resurrect a disposed provider. Regress A→B, dispose A, dispose B => no provider.
- Claim shared run aliases atomically before dispatch; recheck final entries under the claim, reject stale/unreadable entries, and print only aliases whose publication succeeded. Release only the caller's token in `finally`; published aliases survive interruptions. An abandoned admission claim requires explicit repair after checking the originating process/worktree, never automatic deletion.
- Add a headless `rpiv-wf progress` command showing all started RPIV authoring topics across reachable linked worktrees, not just the active topic or execution runs. Show furthest evidence across discover → research → design → plan → implement → validate (artifact presence is not completion), plus explicit Kata issue references/status. Emit Markdown suitable for handoff and deterministic JSON; include evidence-backed overlap/staleness candidates. The view is read-only: no automatic Kata mutation or local daemon fallback.
- Read Kata with `kata list --json` in the caller's working directory and match only actual qualified IDs. Frontmatter accepts arbitrary project names; traversal tracks visited objects so YAML self-references cannot crash the report.
- `activity.timeline` was considered for idempotency. A timeline upsert can deduplicate audit entries but cannot make stage side effects atomic with those entries. Keep this standalone runtime offline-safe: leases prevent overlapping execution, while crash/retry exactly-once behavior still needs stage-specific idempotency keys or transactions. No timeline integration or production writes were added.
- Evolving plan/progress updates go in comments on the active Kata issue. Include commit hashes when they exist; while changes are uncommitted, explicitly say there is no commit yet. Do not create commits without authorization.

## Sequence and acceptance

1. **Revise and review the saved plan first.** Add the pre-implementation safety gate and the independent project-wide progress phase. Update the unsafe provider-restoration design sample. Record the stage-identity, cross-process lock, exact executed-object validation, and reporting contracts before implementing them.
2. **Provider lifecycle regression.** Add out-of-order and idempotent disposal tests; use a single shared provider box with a registration stack. Verify module/global-slot behavior and reset isolation.
3. **Execution validation and park identity.** Bind admission to the exact dispatched object on fresh/resume. Persist/thread a stable park key and stop matching answers by prompt text alone. Tests must prove invalid execution is blocked pre-dispatch and park answers survive prompt edits without crossing repeated occurrences.
4. **Cross-process run lease.** Fresh and resumed execution share one per-run lease. Same-process and actual child-process regressions must refuse resume during active fresh execution without appending rows or repeating side effects. Provider creation/disposal exceptions and failed stages must release the lease; never time-steal a live lease.
5. **Project-wide authoring progress.** Implement `rpiv-wf progress` as a read-only report over linked worktrees and their artifact trees, linked to Kata CLI state. Markdown is handoff-ready; JSON is deterministic. Tests cover multiple worktrees/topics, artifact/status parsing, Kata unavailable, evidence-backed overlap candidates, and zero mutations.
6. **Verify.** Run focused regressions, TypeScript, Biome, package checks, and the full RPIV test suite. Mutation-test each guard where feasible. No provider/model calls, credential access, install, deploy, or push. Commit only after explicit authorization and a clean verification pass.
